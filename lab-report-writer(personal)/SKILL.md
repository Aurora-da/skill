# 实验报告

目标：用最少步骤交付一份可直接提交的 `.docx`（用户另行要求 PDF 时再转）。报告只写实验本身，格式优先服从用户模板。

## 硬约束

1. 只做报告：不改写或重构实验代码，不做无关调研，不动无关文件。代码只用于取真实结果或贴关键片段。
2. 最小代价：材料一次读齐 → 一次判定状态 → 一条分支走到底。同一材料不重复读，不反复试探工具。
3. 格式优先级：用户模板 > `references/format.md` > 通用默认。
4. 不虚构：数据、截图、结果必须来自用户材料或实际运行；拿不到就留占位，并在交付说明中列出。
5. 语言：书面语、第三人称，无口语、无感叹、无"收获很大"式空话；一句只讲一个信息点。
6. 未要求的章节不补：摘要、心得、附录、封面只在模板或要求文档出现时才写。
7. 交付前必须运行 `scripts/check_report.py`，并目视检查首页与含图表的页面。

## 第 1 步：判定状态（先填完这张表，再动手）

| 状态位 | 判定方法 | 对报告的影响 |
| --- | --- | --- |
| 报告模板 | 附件中有 docx/pdf 模板，或明确"按模板" | 有：复制模板结构，按其章节与字体填充 |
| 实验要求 | 有实验指导书、任务书、题目描述 | 必读：抽出实验名称、目的、原理、器材、步骤、结果要求、图表/截图要求、提交格式 |
| 代码 | 有源码、工程目录或可运行脚本 | 有：贴关键片段，运行取真实结果 |
| 过程截图 | 有操作/界面/终端截图 | 有：直接归位到对应步骤 |
| 结果截图/数据 | 有运行结果、输出、图表、数据文件 | 有：直接归位到结果章节 |
| 输出格式 | 用户或要求文档指定 | 未指定：只交 docx；要求 PDF 再转 |

读取要求文档或模板时，只提取章节结构与格式要点，不复述全文；docx/pdf 解析沿用环境已有的文档能力。

判定完成后按下列映射取 `references/prompts.md` 中对应编号，替换其中的 `<>` 占位，作为本次执行指令直接照做；多状态同时命中时，以编号大者为主，编号小者只补其缺的环节。

| 情形 | 提示词 |
| --- | --- |
| 有模板（无论其他材料是否齐全） | P4 |
| 无模板，要求 + 代码 + 截图/数据齐全 | P1 |
| 无模板，有要求与代码，缺截图 | P2 |
| 无模板，只有要求，无代码无截图 | P3 |
| 只有题目或零散信息 | P5 |
| 已有报告需修改/补章节/改格式 | P6 |

## 第 2 步：定骨架

章节顺序以模板为准；无模板时按 `references/content.md` 选择专业分支（通用 / 计算机 / 测量 / 化学），只取该分支的章节，不合并、不扩充。

## 第 3 步：写正文

按 `references/content.md` 的逐节要点与字数上限逐节写。顺序：先结果，再分析，最后结论；结论逐条回应实验目的，不重复罗列结果。

## 第 4 步：图表、代码、截图

- 图：`[[FIG 图1 说明 | 图片路径 | 12]]`（路径可绝对或相对 report.md，第三项为宽度 cm，可省）。
- 表：`[[TAB 表1 说明]]`，下一行起写 Markdown 管道表。
- 代码：`[[CODE 代码1 说明]]`，下一行起写围栏代码。
- 公式：`[[EQ (1)]] 公式文本`。
- 分页：`[[PAGEBREAK]]`。

编号连续，正文先引用再出现（"如图 1 所示"）；图题在图下、表题在表上、均居中；表用三线表；截图只保留关键步骤与关键结果，单张不超过半页宽，图注写清"操作对象 + 结果"。

## 第 5 步：生成 docx（不要手写排版代码）

```bash
python3 scripts/build_report.py report.md -o 实验报告.docx                      # 新建
python3 scripts/build_report.py report.md -o 实验报告.docx --template 模板.docx   # 按模板填充
```

`report.md` 开头用 `key: value` 写元信息（title/course/name/student_id/class_name/major/teacher/date/cover），正文用上面的标记。字体、字号、行距、缩进、三线表、页码全部由脚本处理。直接运行脚本，不要先读脚本源码；只有报错时才定位对应函数，缺依赖则 `pip install python-docx`。

## 第 6 步：校验与交付

```bash
python3 scripts/check_report.py 实验报告.docx
```

按输出的 WARN 逐条修正后重跑，直到只剩可接受提示。需要 PDF 时执行 `soffice --headless --convert-to pdf 实验报告.docx`。用 `present_files` 交付，回复只给三件事：文件、章节清单、待用户补的空项（不超过 5 条）。

## 缺失处理

| 缺什么 | 处理 |
| --- | --- |
| 姓名、学号、班级、日期 | 用 `＿＿` 占位，交付时提示一次，不阻塞 |
| 实测数据 | 有代码就运行取真实输出；无法运行则写"待补充数据"，不编数值 |
| 结果截图（且要求提供） | 运行程序截关键界面或终端；不能截屏则用等宽文本块呈现输出并在图注注明 |
| 过程截图（且要求提供） | 按步骤顺序补关键操作画面，一图一步 |
| 格式要求 | 按 `references/format.md` |
| 实验要求文档 | 先向用户索取；仍无则按题目与模板作最小假设，交付时列出假设 |

## 质量红线

结论与目的脱节、图表无正文引用、编号跳号、单位或有效数字不一致、出现"我/我们"和主观评价、整段照抄实验指导书、截图含无关桌面内容。详见 `references/content.md` 末尾清单。
