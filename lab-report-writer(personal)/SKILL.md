# 实验报告

目标：用最少步骤交付一份可直接提交的 `.docx`（用户另行要求 PDF 时再转）。报告只写实验本身，格式优先服从用户模板。

## 硬约束

1. 只做报告：不改写或重构实验代码，不做无关调研，不动无关文件。代码只用于取真实结果或贴关键片段。
2. 最小代价：材料一次读齐 → 一次判定状态 → 一条分支走到底。同一材料不重复读，不反复试探工具。
3. 格式优先级：用户模板 > `references/format.md` > 通用默认；学校/课程要求与 `format.md` 冲突时一律从学校要求。
4. 不虚构：数据、截图、结果必须来自用户材料或实际运行；拿不到就留占位，并在交付说明中列出。
5. 语言：书面语、第三人称，无口语、无感叹、无"收获很大"式空话；一句只讲一个信息点。
6. 未要求的章节不补：摘要、心得、附录、封面、思考题、安全注意事项只在模板或要求文档出现时才写；脚本默认不生成封面，要求封面时才在元信息写 `cover: simple` 或 `cover: page`。
7. 交付前必须运行 `scripts/check_report.py`，并目视检查首页与含图表的页面；模板模式下字号、字体、行距的 WARN 以模板为准，见第 6 步。

## 第 1 步：判定状态（先填完这张表，再动手）

| 状态位 | 判定方法 | 对报告的影响 |
| --- | --- | --- |
| 报告模板 | 附件中有 docx/pdf 模板，或明确"按模板" | 有：复制模板结构，按其章节与字体填充 |
| 实验要求 | 有实验指导书、任务书、题目描述 | 必读：抽出实验名称、目的、原理、器材、步骤、结果要求、图表/截图要求、提交格式 |
| 代码 | 有源码、工程目录或可运行脚本 | 有：贴关键片段，运行取真实结果 |
| 过程截图 | 有操作/界面/终端截图 | 有：直接归位到对应步骤 |
| 结果截图/数据 | 有运行结果、输出、图表、数据文件 | 有：直接归位到结果章节 |
| 输出格式 | 用户或要求文档指定 | 未指定：只交 docx；要求 PDF 再转 |

读取要求文档或模板时，只提取章节结构与格式要点，不复述全文；docx/pdf 解析沿用环境已有的文档能力。

判定完成后按下列映射取 `references/prompts.md` 中对应编号，替换其中的 `<>` 占位，作为本次执行指令直接照做；多状态同时命中时，以编号大者为主，编号小者只补其缺的环节。

| 情形 | 提示词 |
| --- | --- |
| 有模板（无论其他材料是否齐全） | P4 |
| 无模板，要求 + 代码 + 截图/数据齐全 | P1 |
| 无模板，有要求与代码，缺截图 | P2 |
| 无模板，只有要求，无代码无截图 | P3 |
| 只有题目或零散信息 | P5 |
| 已有报告需修改/补章节/改格式 | P6 |

## 第 2 步：定骨架

章节顺序以模板为准；无模板时按 `references/content.md` 选择专业分支（通用 / 计算机 / 测量 / 化学），只取该分支的章节，不合并、不扩充；模板或要求文档额外给出摘要、目录、符号说明、思考题、安全注意事项、附录时，按模板位置补，不新建分支。

## 第 3 步：写正文

按 `references/content.md` 的逐节要点与字数上限逐节写。顺序：先结果，再分析，最后结论；结论逐条回应实验目的，不重复罗列结果。测量/化学类默认给原始数据表，再给处理结果；分析里写清误差来源，必要时给不确定度（JJF 1059.1）并按 GB/T 8170 修约。

## 第 4 步：图表、代码、截图

- 图：`[[FIG 图1 说明 | 图片路径 | 9]]`（路径可绝对或相对 report.md，第三项为宽度 cm，建议 8～10，最大不超过版心宽 14.6）。
- 表：`[[TAB 表1 说明]]`，下一行起写 Markdown 管道表。
- 代码：`[[CODE 代码1 说明]]`，下一行起写围栏代码。
- 公式：`[[EQ (1)]] 公式文本`。
- 分页：`[[PAGEBREAK]]`。

编号规则：默认"图 1、图 2"全文连续；模板/学校要求按章编号（图 1-1）时全文统一用一套，不混用。正文先引用再出现（"如图 1 所示"）；图题在图下、表题在表上、均居中；表用三线表；截图只保留关键步骤与关键结果，单张不超过半页宽（约 10.5 cm），图注写清"操作对象 + 结果"。

表跨页时脚本已自动重复标题行；续页的"（续表）"字样需手工补。正文引用 `[1]`、`[1,2]`、`[1-3]` 由脚本自动设为上标（学校允许行内方括号时，生成后取消上标即可）。

## 第 5 步：生成 docx（不要手写排版代码）

```bash
python scripts/build_report.py report.md -o 实验报告.docx                      # 新建
python scripts/build_report.py report.md -o 实验报告.docx --template 模板.docx   # 按模板填充
```

Windows 用 `python` 或 `py -3`，macOS/Linux 用 `python3`。

`report.md` 开头用 `key: value` 写元信息（title/course/name/student_id/class_name/major/teacher/date/cover），正文用上面的标记。**默认不生成封面**；要求封面时写 `cover: simple` 或 `cover: page`（两者都单独分页，page 上方留白更多），不用写 `cover: none`。字体、字号、行距、缩进、三线表、页码由脚本处理。直接运行脚本，不要先读脚本源码；只有报错时才定位对应函数，缺依赖则 `pip install python-docx`。

## 脚本已知限制（生成后按此检查）

1. 图表编号由源文件决定，脚本不改写；按章编号就全程写"图 1-1"，`check_report.py` 两种体例都认。
2. 模板模式按标题文本匹配：先"去编号后完全相同"，再双向包含，最后去掉"实验/与/器材"等通用词比较；常见多字少字（"实验环境与器材"对"实验环境"）能匹配。仍匹配失败时追加到文末或评语栏前，并打印 `[warn]`，按模板原词改标题最稳。
3. 模板占位文字（"（模板占位文字）""此处填写"等）在插入内容后自动删除；不认识的占位写法需手工删。模板用"一、二、"编号时，新增的一级章节会自动转成该体例。
4. 模板模式不加页码（沿用模板页脚）；模板本身无页码而要求页码时，手工插入。
5. 页脚只生成"1、2、…"式页码；学校要求"第 X 页 共 Y 页"时需手工改域。

## 第 6 步：校验与交付

```bash
python scripts/check_report.py 实验报告.docx
```

按输出的 WARN 逐条修正后重跑，直到只剩可接受提示；模板模式下字号、字体、行距的 WARN 属于模板差异，保留即可。需要让脚本在存在 WARN 时返回失败（如批量校验）就加 `--strict`，平时不加。

需要 PDF 时优先用 Word"另存为 PDF"；有 LibreOffice 时执行 `soffice --headless --convert-to pdf 实验报告.docx`，本机未安装则不要反复重试，直接说明。用 `present` 交付，回复只给三件事：文件、章节清单、待用户补的空项（不超过 5 条）。

## 缺失处理

| 缺什么 | 处理 |
| --- | --- |
| 姓名、学号、班级、日期 | 用 `＿＿` 占位，交付时提示一次，不阻塞 |
| 组别、同组人、实验地点 | 要求文档出现时补在封面/首部，未出现不写 |
| 实测数据 | 有代码就运行取真实输出；无法运行则写"待补充数据"，不编数值 |
| 结果截图（且要求提供） | 运行程序截关键界面或终端；不能截屏则用等宽文本块呈现输出并在图注注明 |
| 过程截图（且要求提供） | 按步骤顺序补关键操作画面，一图一步 |
| 安全注意事项/应急预案 | 要求时写进步骤末尾或单独小节，未要求不写 |
| 思考题/讨论题 | 要求时在结论后逐题作答，题号与要求文档一致 |
| 参考文献缺页码、DOI、引用日期 | 不编造；缺项留空或标注"待补"，交付说明列出 |
| 格式要求 | 按 `references/format.md`；与学校要求冲突从学校 |
| 实验要求文档 | 先向用户索取；仍无则按题目与模板作最小假设，交付时列出假设 |

## 质量红线

结论与目的脱节、图表无正文引用、编号跳号或两套规则混用、单位或有效数字不一致、出现"我/我们"和主观评价、整段照抄实验指导书、截图含无关桌面内容、参考文献仍按 2015 版或类型标识与正文不对应。详见 `references/content.md` 末尾清单。
