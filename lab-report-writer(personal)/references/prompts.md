# 状态提示词

判定状态后取一个编号，把 `<>` 换成实际路径/信息，整段作为本轮执行指令照做，不必回显给用户。

选择规则：有模板取 P4（其余编号只补缺）；无模板按材料丰度取 P1（齐全）、P2（有代码无截图）、P3（无代码无截图）、P5（仅题目）；已有成品报告要改动取 P6。P1/P2/P3/P5 与 P4 冲突时，格式服从 P4。

---

## P1 材料齐全（要求 + 代码 + 截图/数据）

角色：实验报告撰写执行者。只写本报告，不做其他事。
输入：要求文档 `<>`；代码 `<>`；截图/数据 `<>`；模板 `<>`（无则留空）。
步骤：
1. 读要求文档，抽 8 项：实验名称、目的、原理、环境、步骤、结果要求、图表与截图要求、提交格式。只记要点，不复述原文。
2. 浏览代码结构，定位关键函数与参数（不逐行读、不重构）。
3. 截图按"步骤→结果"归位，重复画面只留一张。
4. 按脚手架章节写正文，每节不超过 content.md 字数上限。
5. 写 `report.md`（含 meta 与 `[[FIG]]/[[TAB]]/[[CODE]]` 标记；默认不生成封面，要求时写 `cover: simple` 或 `cover: page`），运行 `python scripts/build_report.py report.md -o 实验报告.docx`。
6. 运行 `python scripts/check_report.py 实验报告.docx`，修正 WARN 后重跑（模板模式的格式 WARN 以模板为准，见 P6）。
禁止：改代码、加模板外章节、虚构数据、把同一张截图复用两次。
完成判据：docx 可打开，章节齐全，图表编号规则统一且被正文引用，无口语。

## P2 有要求 + 代码，无截图

在上述 P1 基础上执行，差异：
1. 不补过程截图，改用文字步骤描述关键操作与参数。
2. 结果部分：运行代码取真实输出（命令、返回码、日志、指标），以等宽文本块或结果表呈现；要求截图时再补运行窗口截图，并注明"运行结果"。
3. 代码只贴 1～3 段关键片段，各配一句作用说明；完整代码仅在要求附录时放入。
4. 无法运行（缺依赖/缺数据）时：结果章节写"待补充"，列出所需输入与复现命令，不编造数值。
完成判据：结果均来自实际运行或明确标注待补；无空章节。

## P3 纯文档型（有要求，无代码无截图）

1. 跳过代码相关章节与代码片段。
2. 骨架取 A 或 D 分支，重点写原理、步骤、结果现象与讨论。
3. 结果写成可观察现象与过程记录（如配置项、参数、输出特征），无实测数值时用定性描述并说明数据来源。
4. 需要图表时：原理图/流程图用文字描述 + 已有素材，不自行生成伪造结果图。
禁止：为凑篇幅编造数据表或截图。
完成判据：每节都有实质内容，无"待补充"以外的空白。

## P4 按模板填充

输入：模板 `<>`；要求 `<>`；其余材料 `<>`。
步骤：
1. 读模板，列出与报告相关的项：章节名与顺序、标题编号体例（"一、二、"还是"1."）、字体字号、表格样式、页眉页脚、模板已有图表编号的最大值；只记相关项。
2. 把 report.md 的一级标题改成与模板同名、同体例：脚本按"去编号后完全相同 → 双向包含 → 去掉'实验/与/器材'等通用词后比较"匹配。仍匹配不上时会打印 `[warn]`，该章节落到文末或评语栏前，此时按模板原词改标题。
3. 生成：`python scripts/build_report.py report.md -o 输出.docx --template 模板.docx`（Windows 用 `python`/`py -3`）。
4. 打开输出逐项检查：新增章节是否落在正确标题下；模板占位文字（"（模板占位文字）""此处填写"等）由脚本在插入后自动删除，不认识的写法手工删；新增图表编号从模板最大值续编；模板用"一、二、"时脚本已把新增一级标题转成该体例，仍不统一再手工改。
5. 模板本身无页码而要求页码时手工插入；已有页脚保持原样。
禁止：重排模板、替换模板字体、删模板栏目。
完成判据：章节与模板一一对应；新增内容样式与模板一致；无占位文字残留；编号体例统一；模板固定栏目未被破坏。

## P5 仅题目/零散材料

1. 先用一句话向用户确认：实验课程、实验名称、是否有要求文档或模板、是否要求截图（最多三问，能推断则不问）。
2. 用户未补充时，按"课程名 + 实验名称"作最小假设，取对应专业分支骨架，只写题目能支撑的内容。
3. 所有假设与缺失项在交付说明中列出（不超过 5 条）。
禁止：编造实验步骤细节与结果数据来填满骨架。
完成判据：骨架完整、内容不超出已知信息、假设已明示。

## P6 修改已有报告

输入：现有报告 `<>`；修改要求 `<>`；补充材料 `<>`。
1. 先跑 `python scripts/check_report.py 已有报告.docx`，汇总 WARN；模板模式下字号、字体、行距的 WARN 以模板为准，其余按清单修正。
2. 只改要求涉及的部分，保持其余段落、编号、样式不动。
3. 增删章节后重排图表编号与正文引用：全文连续就用图 1、图 2；模板按章就用图 1-1 并与模板既有编号衔接，全文只留一套规则。
4. 改动涉及封面、参考文献或引用序号时，核对 `cover` 设置（默认不生成封面）、GB/T 7714-2025 类型标识（含 `/OL`）与正文上标（脚本自动加，学校要求行内方括号时取消）。
5. 重新生成或就地修改后重跑 check，输出改动清单（改了什么、为什么）。
禁止：整体重写、顺手"优化"未要求的段落。
完成判据：修改点与要求逐条对应；图表编号规则统一；原格式未被破坏。
